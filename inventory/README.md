# Inventory

What the Rust rewrite must reproduce, extracted from the C tree. Every `.json` and `.md` here is
generated by `gen/<section>.py`; none is edited by hand. Each records the C commit it describes
(`c-commit`, the last commit outside the rewrite's own paths, `-dirty` if the C tree has local
changes). Paths that belong to the rewrite are listed in `NOT_C_TREE` in `gen/common.py`; add
new top-level rewrite paths there, or every rewrite-only commit makes the inventory look stale.

```sh
python3 inventory/gen/all.py           # regenerate everything
python3 inventory/gen/all.py --check   # also fail if any committed output is stale
```

Run `--check` after the C tree moves; a generator that fails its self-checks writes nothing.
Lint generators with `scripts/pythonlint.sh inventory/gen/*.py`.

## Sections

| section | what it holds |
|---|---|
| `abi` | Exported functions and prototypes, every public constant with its compiler-computed value and C type, struct sizes and field offsets, typedef sizes, strerror tables, symbol history, soname, version script, pkg-config and curl-config. |
| `options` | CURLOPT, CURLMOPT, CURLSHOPT, CURLINFO, URL API parts and flags, header origins, websocket flags: number, type class, `curl_easy_option_*` row, gcc typecheck class, man page metadata, reserved numbers. |
| `cli` | curl tool options (docs vs `aliases[]` table), `--write-out` variables, exit codes, environment and config-file lookup, generated `src/` files. |
| `features` | Protocol schemes, `curl_version_info` features and the test-gating names derived from them, build options, backends per category, environment variables libcurl reads. |
| `quirks` | Claims from KNOWN_BUGS, TODO, EXPERIMENTAL, DEPRECATE and KNOWN_RISKS. All are hypotheses until a test reproduces them. |
| `tests` | Every `tests/data` case with keywords, features, servers and runner; DISABLED; libtest, unit and tunit programs; the pytest suite; test servers. |

## Reading the data

- **Layouts are per target.** `abi.json` records the `target` it was probed on. Struct layouts
  and type sizes hold for that target only.
- **Discrepancies are data.** Where two C sources disagree (docs against the header, the docs
  against the option table), the generator keeps both sides under `discrepancies` and does not
  pick one. Run the C build before deciding which side is right.
- **Doc-derived fields are claims.** Protocol lists, DEFAULT text and anything taken from prose
  describe what the C docs say, not verified behaviour.
- **Some tables are hand-written.** They are anchored to the C sources by checks:
  - the backend library and macro table in `gen/features.py`;
  - the `<server>`-keyword-to-program map in `gen/tests.py`.

  When one of these checks fails, update the table to match the C sources. Do not weaken the
  check.
